# 智力倒水游戏：首版 50 关逐关配置方案

> 说明：瓶内颜色顺序统一采用**底部 → 顶部**。例如 `红蓝蓝黄` 表示瓶底是红色，瓶口顶部是黄色。`空瓶` 表示没有液体。每种颜色总量均为 4 层，瓶容量为 4。
> 本文是可落地的初版关卡配置草案。特殊瓶会改变可观察信息或可执行动作，正式上线前必须使用项目 Solver 按真实规则逐关验证可解性，并按实测步数/分支数调整。

## 全局配置
- 瓶容量：4 层；颜色单位：每色 4 层。
- 普通倒水：源瓶顶部连续同色尽可能倒出，受目标剩余容量限制；目标瓶为空或顶层同色才可接收。
- 空瓶：仅作为临时空间，不含颜色。
- 遮罩瓶：液体真实参与规则，但瓶身罩住、不可直接观察；每关独立配置解锁阈值。建议以“已完成的目标颜色瓶数”计数，解锁后播放布罩掉落动画。
- 隐藏瓶：最多 4 层，最多 3 层隐藏；本方案隐藏底部 1–2 层。倒出可见顶部液体后揭示下一层；隐藏颜色不能出现在提示文案中。
- 底部漏水瓶：玩家主动点击触发；源瓶底色必须匹配目标瓶顶色；目标瓶默认不能是空瓶；每次成功漏出 1 层。
- 所有特殊瓶效果与动画分离：先提交逻辑状态，再播放动画；动画期间输入锁定。

## 难度曲线与验收
| 关卡段 | 设计目的 | 主要机制 | 建议验收重点 |
|---|---|---|---|
| 1–5 | 认识基础操作 | 普通倒水、空瓶 | 首次操作提示清晰，2–4 步能看懂规则 |
| 6–10 | 练习空间规划 | 减少空瓶、增加颜色 | 不出现无解开局，提示不泄露答案以外信息 |
| 11–20 | 建立顺序意识 | 多色交错、单空瓶 | 重点验证死局识别与撤销体验 |
| 21–30 | 引入遮罩瓶 | 阈值解锁、遮罩动画 | 解锁条件只按逻辑状态统计，不受动画帧影响 |
| 31–40 | 引入隐藏瓶 | 底部逐层揭示 | 隐藏层不被提示/预览/调试 UI 意外泄露 |
| 41–45 | 引入底部漏水 | 点击触发、颜色匹配 | 不匹配时状态与步数完全不变 |
| 46–50 | 组合挑战 | 三类特殊瓶组合 | Solver 与正式规则完全一致，验证可解性和体验 |

## 正式上线前必须自动化验证
1. 每关每种颜色恰好 4 层，瓶容量不超过 4，瓶子层数总和守恒。
2. 普通倒水规则与 Solver 使用同一份纯函数实现。
3. 遮罩瓶的解锁阈值可达；不能要求玩家先完成一个被自身遮罩条件锁死的目标。
4. 隐藏瓶所有真实层参与 Solver，但 UI、提示与关卡预览不得泄露隐藏信息。
5. 底部漏水操作要有可达的合法目标；若该关设计为必需机制，Solver 解法中必须至少使用一次漏水操作。
6. 对每关记录最短解步数、状态扩展数、是否必须使用特殊机制、平均试玩耗时；据此调整难度。
7. 当前初始布局为结构化草案，特殊机制关卡尤其需要 Solver 验证后再锁定为正式数据。
