# 游戏 UI 工业级设计与资产交付工作流

本技能借鉴业界优秀游戏 UI 设计工作流（Spec-Kit + Contracts 体系），为游戏开发提供端到端的视觉一致性与工程交付标准。

## 核心原则

1. **契约优于生成（Contracts First）**：
   - 在生成任何页面或素材前，必须先在契约文件中锁定：光源方向（如 `top-left`）、色彩系统（Tokens）、圆角阶梯、材质规范（如玻璃/亚克力/果冻水体）。
   - 禁止在不同页面中随意引入契约外的光照方向和材质系统。
2. **底模无文字铁律（No-Text Policy）**：
   - 生成按钮、卡片、底板、弹窗切图时，**严禁将文字烘焙进图片中**。
   - 所有图片素材必须为纯净底模，文字、数字、标签由代码（CSS / Canvas / TextMesh）在运行时排版渲染，以支持多语言、字号动态缩放与清晰度。
3. **分阶段严格门禁（Approval Gates）**：
   - 阶段 1：策划方案、PRD 与状态机交互逻辑未核准前，不盲目生图；
   - 阶段 2：基准原型未核准前，不定稿风格；
   - 阶段 3：风格契约未核准前，不批量延展多页面；
   - 阶段 4：页面整体效果未核准前，不拆解独立组件切图。
4. **组件状态全覆盖（State Completeness）**：
   - 任何交互元素必须定义完整状态机：`default`（默认）、`hover`（悬停）、`pressed`（按下）、`disabled`（禁用）、`selected`（选中）。
5. **9-Slice（九宫格拉伸）标准**：
   - 可拉伸的底框、按钮、进度条，必须明确定义拉伸保留边距 `[left, right, top, bottom]`，杜绝非等比拉伸导致的变形与模糊。

## 7 大执行阶段

### 阶段 1：需求策划与状态机定义 (Product Design)
- 明确核心循环与交互状态机（如瓶子：空闲 Idle、选中 Selected、倾倒 Pouring、灌入 Filling、结算 Settled）。
- 定义各状态下的视效触发条件与音效时机。

### 阶段 2：基准原型设计 (Prototype Baseline)
- 先以单张核心游戏界面（如游戏主对局屏）验证信息层级、主操作视线聚焦（3秒内识别主玩法）、顶部资源区与底部控制区。

### 阶段 3：视觉契约确立与风格冻结 (Style Contract)
- 冻结光源方向：统一为 Top-Left 45° 柔和漫反射。
- 冻结色彩 Tokens：主行动色、警告色、成功色、各液体色系饱和度与明度标准。
- 冻结几何规范：瓶身圆角、外边框描边、按钮高度与内边距。

### 阶段 4：页面延展 (Screen Extension)
- 基于基准风格延展：关卡选择、每日挑战、规则弹窗、胜利结算、设置面板。
- 确保所有延展窗口使用统一的毛玻璃遮罩、窗口圆角与关闭按钮规范。

### 阶段 5：组件无文字拆解与雪碧图 (Component Breakdown)
- 输出透明背景 PNG 素材或雪碧合图。
- 严格遵循 `no-text` 规则，元素之间保持清晰间距（≥ 8px），避免相交粘连。

### 阶段 6：切片与独立素材提取 (Sprite Splitting)
- 按连通域算法或固定网格提取各独立元素。
- 输出带语义命名的透明单图（如 `btn-undo-normal.png`, `btn-undo-pressed.png`）。

### 阶段 7：Atlas 图集与代码交付 (Atlas & Integration)
- 将零散小图合并为 2 的幂次方尺寸（POT, 如 512x512 / 1024x1024）图集，减少 HTTP 请求与 GPU 切换开销。
- 标注 9-slice 参数，以代码或配置文件形式交付前端组件使用。
