# 游戏 UI/UX 工业级全流程与动效架构技能规范

本规范吸收并融合了开源游戏开发社区三大核心技能规范（`gamedev-skills/game-ui-ux`、`game-feel`、`GameDesignOS`），为游戏工程提供端到端的**视觉设计、渲染架构、微动效质感与状态流控**标准。

---

## 一、核心设计哲学与铁律

1. **契约优于生成（Contracts First）**：
   - 必须在开发前冻结全局视觉契约：统一主光源方向（如 `Top-Left 45°` 漫反射）、色彩 Tokens（高饱和度纯色 + 受光顶色 + 暗部阴影色）、圆角阶梯与材质规范。
   - 严禁不同界面出现相互冲突的光影逻辑和随意的色彩漂移。

2. **底模无文字铁律（No-Text Policy）**：
   - 所有按钮、卡片、底板、弹窗的图像素材中，**严禁烘焙静态文字**。
   - 素材仅输出纯净图形与光影底模，文字与数字必须通过运行时（CSS / SVG Text / Canvas / TextMesh）排版渲染，以原生支持多语言本地化、动态排版及字号清晰度。

3. **双层解耦与视口保护（Playfield Protection）**：
   - **物理场景层与 UI 覆盖层分离**：底层 Canvas/WebGL 专注于流体、碰撞与物理渲染；顶层 DOM/SVG 专注做高分辨率矢量 HUD 与交互菜单。
   - **核心操作区保护**：顶部 HUD 与底部控制栏固定高度，中央对局区（Playfield）自适应缩放，严禁 UI 遮挡关键游戏实体或阻断交互焦点。
   - **安全区适配（Safe Area）**：顶部必须适配手机刘海与微信小游戏胶囊按钮（`padding-top: max(env(safe-area-inset-top), 44px)`），底部规避手势横条。

4. **游戏爽感与微动效（Game Feel & Micro-Juice）**：
   - **物理次级动效（Secondary Motion）**：物体停止移动时具有阻尼回弹（Damped Oscillations），液体倾倒与落液具有表面张力微拱、涌动与飞溅小水珠。
   - **多模态即时反馈**：视觉冲击（微光/粒子）+ 听觉（随充盈度动态提升音高 Pitch Ramping）+ 触觉（轻微触感震动）。
   - **温和非惩罚交互**：非法操作采用柔和的短晃动（Shake）与提示音，禁止弹出生硬刺眼的红色报错框。

5. **状态图闭环与死局流控（Cycle & Deadlock Circuit Breaker）**：
   - **防假死挂起**：当游戏有效移动仅剩同色在容器间来回倒（如 `A ↔ B` 封闭环）且无法推进状态时，底层必须具备**死循环检测**，在 400ms 内弹出非惩罚性死局引导（撤回 / +1容器道具 / 重置），严禁把玩家置于无尽死循环中发呆。
   - **可解性守卫（Solvability Guard）**：关卡生成必须通过 Solver 自动求解验证，确保初始局必存在最优通关路径。

6. **9-Slice（九宫格拉伸）标准**：
   - 可拉伸的底框、按钮、进度条，必须明确定义拉伸保留边距 `[left, right, top, bottom]`，杜绝非等比拉伸导致的变形与模糊。

## 二、端到端全流程执行阶段

### 阶段 1：状态机与循环设计 (Core Loop & FSM)
- 明确游戏 30 秒微心流闭环（Action $\rightarrow$ Feedback $\rightarrow$ Reward $\rightarrow$ Repeat）。
- 定义每个实体的完整状态机（如容器：空闲 `Idle`、选中 `Selected`、倾斜 `Tilting`、灌注 `Pouring`、完成 `Complete`、受阻 `Invalid`）。
- 定义各状态下的视效触发条件与音效时机。

### 阶段 2：基准视口与安全区原型 (Playfield Prototype)
- 规划手机端自适应布局，明确顶部安全区、底部控制区及中央自适应舞台。
- 确保主操作视线聚焦，玩家进入界面后 3 秒内能直观识别核心交互目标。

### 阶段 3：视觉契约确立与风格冻结 (Style Contract)
- **光源与深度**：统一视平线与 2.5D 透视角度（如 15° 俯视倾角、表面张力微拱深度 $RY$）。
- **色彩与明暗**：定义主色 `hex`、顶光受光色 `topHex`、暗部阴影色 `shadeHex`。
- **材质质感**：高光通透度、玻璃折射贴图、流体晶莹反光与高光线条宽规范。

### 阶段 4：页面延展与交互组件化 (Screens & Modals)
- 基于基准风格延展主对局、关卡面板、每日挑战、胜利庆祝与死局求助弹窗。
- 所有弹窗统一步调：暗色柔光毛玻璃背景遮罩、事件阻断隔离、平滑弹出与收起补间。

### 阶段 5：Game Feel 动效与手感调优 (Juicing & Polish)
- **微动效**：配置贝塞尔曲线（如 `cubic-bezier(0.25, 1, 0.5, 1)` 弹性入场）。
- **粒子与水花**：落水中心涌动椭圆（Impact Dome）+ 伴随水滴跳跃（Pearl Droplets）+ 微小气泡浮动。
- **音效多模态**：根据水位比例动态调制音高（Pitch 随水位由 400Hz 爬升至 900Hz），完成全瓶时触发水晶清脆和弦音。

### 阶段 6：组件无文字拆解与雪碧图提取 (Component Slicing)
- 输出带透明通道（RGBA 32-bit）的纯净 PNG 素材。
- 严格遵循 `No-Text` 规则，元素四周保留 ≥ 8px 安全间距，杜绝边缘羽化粘连。

### 阶段 7：Atlas 图集与工程集成交付 (Atlas & Engineering)
- 零散素材拼合为 POT（Power-of-Two, 如 512x512 / 1024x1024）图集，降低 Draw Call 与纹理切换开销。
- 标注 9-slice 参数及对应 CSS / Canvas 引用路径，交付给工程代码无缝使用。
